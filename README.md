# Baac_Exam ระบบซ้อมสอบ ธ.ก.ส.

เปิดใช้งานได้ที่ https://pangivn-cell.github.io/baac-exam/

- ฝึกทำข้อสอบ: ความรู้ความสามารถทั่วไป และความรู้เฉพาะตำแหน่งงานสินเชื่อ ความยากปรับตามผล
- สอบจริง (Mock Exam): จับเวลา ส่งอัตโนมัติ ระบบกันโกง
- คลังความรู้: อัปโหลด PDF/DOCX/TXT/HTML ให้ AI ย่อยเป็นบัตรความรู้หรือดึงเป็นคลังข้อสอบ แล้วแบ่งเข้าคลังกลาง (Firebase)
- อัปโหลดขึ้น Google Drive ก่อน แล้วค่อยย่อยทีหลัง: ไฟล์ขึ้น Drive ทันที ปิดหน้าระหว่างรอได้ กลับมาเปิดเว็บแล้วระบบทำต่อจาก Drive
- สอบถาม AI, อันดับ, ประวัติสอบ, บันทึกโจทย์กันซ้ำ (ซิงก์ข้ามเครื่องเมื่อล็อกอิน)
- คิวและคลังส่วนตัวซิงก์ข้ามเครื่อง: อัปโหลดที่มือถือ ไปทำต่อ/อ่านบัตรความรู้บนคอมได้ (Firestore ใต้บัญชีตัวเอง)
- แอดมินเปลี่ยนชื่อรายวิชาได้ · แก้บัตรแล้วเลือกได้ว่าผูกกับวิชาไหน · กันไฟล์ซ้ำทั้งในเครื่อง บัญชี คลังกลาง และ Google Drive

ฟีเจอร์ AI ต้องใส่ Gemini หรือ OpenAI API key ของตัวเองในเมนู ตั้งค่า AI (key เก็บในเบราว์เซอร์เท่านั้น)

## ซิงก์คิวและคลังข้ามเครื่อง

เมื่อผู้ใช้ล็อกอิน เอกสารของตัวเองจะถูกซิงก์ผ่าน Firestore ใต้พาธของผู้ใช้เอง

```
users/{uid}/docs/{key}              meta + สถานะคิว + lease (เล็ก)
users/{uid}/docs/{key}/pages/{i}    ข้อความหน้า แบ่งก้อน ~600 KB (นับไบต์จริง)
users/{uid}/docs/{key}/cards/{i}    บัตรความรู้/ข้อสอบ แบ่งก้อน
users/{uid}/figs/{figId}            รูปประกอบ (บีบแล้ว < 700 KB, ดึงเมื่อต้องแสดง)
```

- `key` = `s` + SHA-256 ของไฟล์ (ไฟล์เดียวกันทุกเครื่องใช้คีย์เดียว) · ไม่มี sha ใช้ `l` + รหัสในเครื่อง
- **lease 3 นาที** กันสองเครื่องย่อยไฟล์เดียวกันพร้อมกัน · เครื่องที่ปิดไป หมดอายุแล้วเครื่องอื่นรับต่อจากจุดเดิมได้
- ระหว่างย่อย ระบบส่งหน้า/บัตร/รูปขึ้นเป็นระยะ เพื่อให้อีกเครื่องรับงานต่อได้โดยไม่ต้องเริ่มใหม่
- บัตรที่แก้/ลบ และการล้างบัตรตอน "อ่านทุกหน้าใหม่" มี revision ใน meta ให้เครื่องอื่นตามให้
- รูปประกอบดึงเมื่อต้องแสดง/ต้องใช้กับ AI ไม่โหลดทั้งคลังตอนเปิดหน้า
- เอกสารของบัญชีอื่นบนเบราว์เซอร์เดียวกันจะไม่ถูกส่งเข้าบัญชีที่กำลังล็อกอิน และไม่ขึ้นในเมนู

**ต้องเผยแพร่กฎใน `firestore.rules`** (มี `match /users/{uid}/docs` และ `/figs` เพิ่มแล้ว) ไม่งั้นระบบจะเก็บงานไว้ในเครื่องเหมือนเดิมและขึ้นข้อความเตือนในหน้าคลังความรู้

ทดสอบสองเครื่องโดยไม่ใช้ Firestore จริง:

```bash
node tests/smoke-sync.mjs
```

## จัดการรายวิชา · ผูกบัตรกับวิชา · กันไฟล์ซ้ำ

### 1) เปลี่ยนชื่อรายวิชา (ผู้ตรวจ/แอดมิน)

หน้าคลังความรู้ → **ข้อมูลในคลังกลาง** → **จัดการรายวิชา** → กด **เปลี่ยนชื่อ** ข้างวิชา

หรือกดไอคอน **✏️** ข้างชื่อวิชาในเมนูซ้ายได้เลย (มีทุกวิชาสำหรับผู้ตรวจ/แอดมิน)
- วิชามาตรฐาน/วิชาที่แอดมินเพิ่ม: เปลี่ยนชื่อให้ทุกคนเห็น
- วิชาที่มาจากไฟล์: เปลี่ยนเฉพาะชื่อที่แสดงในเมนูของเครื่องนั้น (ชื่อไฟล์ต้นฉบับไม่เปลี่ยน)

ระบบจะ:
- เขียน `config/subjects` เป็น `rename:{id:ชื่อใหม่}` และ `alias:{ชื่อเดิม:ชื่อใหม่}`
- ย้าย `topic` ของบัตร/ข้อสอบในเครื่อง, เอกสาร, คลังกลาง (`kb`) และงานรออนุมัติ (`subs`) ให้ตรงกัน
- เก็บชื่อเดิมไว้เป็นคำค้น และให้เครื่องอื่น/ผู้ใช้อื่นแปลงชื่อเดิมเป็นชื่อใหม่ตอนโหลด (`topicName()`)

เปลี่ยนชื่อซ้ำหลายครั้งได้ · วิชาที่เพิ่มเองก็เปลี่ยนชื่อได้ · ชื่อใหม่ห้ามซ้ำกับวิชาที่มีอยู่

**ลบวิชา** (ปุ่มถังขยะ) มี 2 ทาง:
- **ลบแค่รายวิชา** = เอาออกจากเมนูของทุกคน แต่เก็บบัตร/ข้อสอบ/ไฟล์ไว้ครบ เปิดกลับได้ที่ จัดการรายวิชา
- **ลบวิชาและข้อมูล** = ลบบัตร/ข้อสอบทั้งหมดในวิชานี้ (กู้คืนไม่ได้)

วิชาที่มาจากไฟล์จะมีตัวเลือก **ซ่อนวิชานี้ (เก็บข้อมูล)** ซึ่งเก็บเอกสารและบัตรไว้ครบเช่นกัน

### 2) ผูกบัตรความรู้กับรายวิชา

กด **แก้** ที่บัตร (หรือข้อสอบในคลัง) → มีช่อง **รายวิชา/หัวข้อ** ให้เลือกจากวิชาทั้งหมด
(ความรู้ความสามารถทั่วไป + ความรู้เฉพาะตำแหน่ง + วิชาที่แอดมินเพิ่ม) แล้วบันทึก
- บัตรในคลังกลาง: เปลี่ยน topic ใน `kb/{id}` ให้ทุกคนเห็นตอนซิงก์
- บัตรในคลังส่วนตัว: เปลี่ยน topic + ซิงก์ขึ้นบัญชีทันที
- ระบบล้าง embedding เดิมและสร้างใหม่ให้ค้นหา/ถาม AI ตรงกับหัวข้อใหม่

### 3) กันไฟล์ซ้ำ

ตรวจ 4 ชั้นก่อนย่อย:
1. **ชื่อเดิม + SHA เดิม** → อัปเดตแค่การตั้งค่า ไม่ประมวลผลซ้ำ
2. **SHA เดิมแต่ชื่อต่าง** → ใช้เอกสารเดิม ข้ามไฟล์ใหม่
3. **SHA เดิมในบัญชี/คลังกลาง** → ใช้ของเดิม (รวมถึงเครื่องอื่น)
4. **SHA เดิมบน Google Drive** → ใช้ไฟล์เดิม ไม่สร้างไฟล์ซ้ำ (ต้องมี `findsha` ใน `Code.gs` รุ่นใหม่)

ถ้าไฟล์ถูกบันทึกใหม่จนไบต์ต่างแต่ **เนื้อหาเดิม** ระบบใช้ `txtSha` (ลายนิ้วมือข้อความ) กันให้อีกชั้น
และตอนย่อยจะข้าม **บัตร/ข้อสอบที่ซ้ำกันทุกตัวอักษร** พร้อมนับจำนวนที่ข้ามไว้ในการ์ดเอกสาร

> ถ้าเคย redeploy `Code.gs` แล้ว ให้วางรุ่นล่าสุดอีกครั้งเพื่อให้มี action `findsha` (ถ้าไม่ redeploy ยังกันซ้ำด้วย SHA/ชื่อได้ แต่จะไม่ตรวจไฟล์เดิมบน Drive)

ทดสอบ:

```bash
node tests/smoke-features.mjs
```

## อัปโหลดขึ้น Google Drive ก่อน

หน้าคลังความรู้จะเสนอตัวเลือก **อัปโหลดขึ้น Google Drive ก่อน แล้วค่อยย่อยทีหลัง** เมื่อ

1. ผู้ใช้ล็อกอินแล้ว (ต้องใช้ Firebase ID token ตรวจสิทธิ์กับ Apps Script) และ
2. แอดมินตั้งตัวรับไฟล์ Apps Script ไว้แล้วใน `config/srcdirs` (ดูวิธีติดตั้งหัวไฟล์ `apps-script/Code.gs`)
   · ถ้าเคยติดตั้งไว้แล้ว ให้วาง `Code.gs` ฉบับใหม่แล้ว "ทำให้ใช้งานได้" อีกครั้ง รุ่นใหม่ตรวจไฟล์ซ้ำด้วย SHA-256
     ทำให้อัปโหลดไฟล์ที่แก้ไขแล้วแต่ใช้ชื่อเดิมได้ไฟล์ใหม่ (ไม่หยิบเนื้อหาเก่ากลับมาใช้)

ลำดับการทำงาน

1. เลือกไฟล์ → ส่งไบต์ขึ้น Drive เป็นชิ้น (8 MB) พร้อมแถบความคืบหน้า → ได้รหัสไฟล์กลับมา
2. สร้างเอกสารสถานะ `queued` พร้อม `driveId`/`srcFile` (ไม่ผูกสำเนาไฟล์กับเอกสาร · ถ้าต้องดึงมาอ่านใหม่ ระบบมีแคชต้นฉบับชั่วคราวไม่เกิน 300 MB)
3. ถึงคิวจึงดึงไฟล์จาก Drive มาอ่านข้อความ/รูป แล้วให้ AI ย่อยตามปกติ (ทำต่อจากจุดเดิมได้)
4. ปิดหน้าระหว่างย่อยได้ · เปิดเว็บใหม่ในเครื่องเดิม `autoRetry` จะหยิบงานที่ค้างขึ้นมาทำต่อ
   (รายการงานเก็บใน IndexedDB ของเบราว์เซอร์นั้น ไม่ได้ซิงก์ข้ามเครื่อง)

ถ้าส่งขึ้น Drive ไม่ได้ (ยังไม่ล็อกอิน พื้นที่เต็ม เน็ตหลุด) ระบบจะถอยไปอ่านและย่อยในเครื่องให้เหมือนเดิม ไม่ทำให้งานหลุด

ทดสอบเส้นทางนี้โดยไม่ใช้ Drive/AI จริง:

```bash
node tests/smoke-drive-first.mjs
```

ต้องมี Chrome และ Python 3 (สคริปต์จะเปิดเซิร์ฟเวอร์และ Chrome headless ให้เอง · ตั้งค่า `CHROME_BIN`, `PYTHON`, `PORT` ได้)

ข้อควรระวัง
- โค้ดที่รันตอนโหลดหน้าแล้วเรียกฟังก์ชันจากไฟล์อื่น ให้ห่อด้วย `onAppReady(...)` (อยู่ใน `core.js`)
- ก่อนขึ้นเว็บทุกครั้ง: `sh bump.sh <เวอร์ชันใหม่>` เพื่อให้เบราว์เซอร์ทุกคนโหลดไฟล์ใหม่
- ทดสอบในเครื่องต้องเปิดผ่านเว็บเซิร์ฟเวอร์ เช่น `python -m http.server --directory baac-exam`
